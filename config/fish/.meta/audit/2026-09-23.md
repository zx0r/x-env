## 🔴 CRITICAL (Security, SLA Violations, Correctness Bugs)

### C1. `gemini.fish` — Stale Keychain Pattern (Paradigm Violation)

**File:** [`functions/gemini.fish`](../../functions/gemini.fish) · Lines 3–7  
**Issue:** Uses the **purged** macOS Keychain pattern (`/usr/bin/security find-generic-password`). Exact same dead code that was removed from `claude.fish`.  
**Fix:**
```fish
function gemini --wraps=gemini --description "Gemini CLI with JIT SOPS token"
    set -lx GEMINI_API_KEY (get-secret GEMINI_API_KEY)
    or begin; echo "✗ GEMINI_API_KEY not found. Run: add-secret --ram GEMINI_API_KEY" >&2; return 1; end
    command gemini $argv
end
```

### C2. `99-secrets.fish` — `eval` on SOPS data without key name validation

**File:** [`conf.d/99-secrets.fish`](../../conf.d/99-secrets.fish) · Lines 134–143  
**Issue:** `with-secret` generates `set -lx KEY VALUE` strings via `jq` and `eval`s them. The `@sh` escapes the *value* but the SOPS key *name* is interpolated raw. A malicious key name (e.g., `FOO; rm -rf /`) would execute arbitrary code.  
**Fix:** Add key name validation before eval:
```fish
for line in $fish_exports
    if not string match -rq '^set -lx [A-Za-z_][A-Za-z0-9_]* ' "$line"
        echo "✗ Error: Invalid key name in SOPS namespace '$namespace'." >&2
        return 1
    end
end
eval $fish_exports
```

### C3. `10-runtimes.fish` — Cache write race condition (concurrent Tmux panes)

**File:** [`conf.d/10-runtimes.fish`](../../conf.d/10-runtimes.fish) · Lines 53, 61, 69, 77  
**Issue:** Background cache regeneration writes directly to the final file (`> starship.fish &`). If multiple terminals open simultaneously (Tmux session restore), concurrent writes corrupt the cache.  
**Fix:** Write to a PID-specific temp file, then atomic `mv`:
```fish
starship init fish > "$cache_dir/starship.fish.$fish_pid"
and command mv "$cache_dir/starship.fish.$fish_pid" "$cache_dir/starship.fish" &
```

### C4. `generate_gpg_key.fish` — Passphrase visible in process list

**File:** [`functions/generate_gpg_key.fish`](../../functions/generate_gpg_key.fish) · Lines 39–41  
**Issue:** Passes passphrase as CLI argument (`--passphrase "$passphrase"`), visible via `ps -Eww`. Also: GPG key generation is **obsolete** with Secretive SSH signing.  
**Fix:** **Delete the file.** GPG signing is fully deprecated.

### C5. `memory_optimizer.fish` — Destructive crontab wipe

**File:** [`functions/memory_optimizer.fish`](../../functions/memory_optimizer.fish) · Lines 50–52  
**Issue:** `echo "0 * * * * /usr/sbin/purge" | crontab -` **overwrites the entire crontab** without preserving existing entries. Also, `purge` requires `sudo` and silently fails in user cron.  
**Fix:** **Delete the file.** Automated memory purging is an anti-pattern on macOS.

### C6. `20-abbr.fish` — Broken placeholder expansions

**File:** [`conf.d/20-abbr.fish`](../../conf.d/20-abbr.fish) · Lines 289–294, 332, 356–360  
**Issue:** Abbreviations use `{argv}`, `{url}`, `{port}` placeholders — Fish `abbr` does not interpolate these. Expanding `psgrep` literally executes `grep -i -e VSZ -e {argv}`.  
**Fix:** Use `--set-cursor` with `%` marker:
```fish
abbr -a psgrep --set-cursor 'ps aux | grep -v grep | grep -i -e VSZ -e %'
```

### C7. `02-brew.fish` — Auto-installer hijacks shell init

**File:** [`conf.d/02-brew.fish`](../../conf.d/02-brew.fish) · Lines 21–24  
**Issue:** If Homebrew binary is missing, the file runs `curl | bash` to install it — blocking shell init indefinitely, requiring `sudo` input. Provisioning ≠ shell startup.  
**Fix:** Replace with a non-blocking warning:
```fish
if not test -x /opt/homebrew/bin/brew
    echo "⚠ Homebrew not installed. Run: mise run L1_bootstrap" >&2
    return
end
```

### O7. `20-abbr.fish` — Deprecated `egrep`

**Line:** 211
